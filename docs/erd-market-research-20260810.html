0세 줄 요약

협업 엔진과 AI 연동은 이미 상용 서비스급이고, 부족한 것은 대부분 "보여주고 나눠주는" 표면 기능입니다.

이미 강한 것

  • 실시간 동시편집 엔진 — 소프트 락, presence, 드래그 중계, Undo/Redo까지. drawSQL은 이걸 월 $59 플랜에 넣습니다.
  • MCP 서버 내장 — 조사한 6개 경쟁 서비스 중 어디에도 없는 기능. AI-네이티브 포지션의 핵심 자산.
  • DDL 임포트 + 관계 자동 추론 + LLM 도메인 분류 — FK 없는 실무 스키마를 알아서 정리해주는 조합은 희소.

비어 있는 것

  • 공유 링크/딥링크 없음 — URL로 특정 방을 열 수 없어 "이거 봐" 한 마디가 안 됨. 웹 도구의 테이블 스테이크.
  • 카디널리티 표기 없음 — 관계선이 방향·배수 없는 곡선 하나뿐. ERD 도구로서 표기법(IE/까마귀발)은 기본기.
  • MySQL 외 방언, PDF, 미니맵, 다크/라이트 전환 — 경쟁 서비스 대부분이 갖춘 기본 편의 기능.

최우선 3가지

  • ① 방 딥링크 + 읽기전용 공유 링크 — 도입 장벽이 가장 낮고 확산 효과가 가장 큼.
  • ② 관계 카디널리티 표기 — "ERD처럼 보이게" 만드는 최소 요건.
  • ③ AI 스키마 리뷰 — Anthropic API 연동이 이미 있어 저비용으로 drawSQL 유료 기능을 따라잡는 차별화.

1ERD Studio 현재 기능 인벤토리

README가 아니라 코드에서 직접 확인한 목록입니다. 각 카드는 실제 소스 디렉터리 단위와 대응합니다.

캔버스 · 뷰어
  • SVG 렌더링 + 베지어 관계선 라이브러리 없는 자체 구현, 107테이블 시드에서 동작
  • 도메인 그리드 자동 레이아웃 저장된 좌표가 있으면 우선 적용
  • 드래그 팬 / 휠 줌 / 전체보기 리셋 rAF transform 조작으로 리렌더 없음
  • 노드 클릭 → 관계 강조 + 상세 패널 PK·UK·FK 배지, 참조/피참조 목록
  • 테이블·컬럼·설명 검색, 도메인 필터 매칭 외 노드 dim 처리
  • 허브 테이블 강조 표시
실시간 협업
  • WebSocket 동시편집 저장 버튼 없이 즉시 반영·자동 저장
  • 접속자 아바타 + 탭 중복 제거 presence
  • 테이블 단위 소프트 락 "○○님이 편집 중" 배지, 끊기면 30초 내 자동 해제
  • 드래그 위치 실시간 중계 50ms 스로틀, mouseup 시 확정
  • Undo/Redo 50단계 역연산 기반, 자기 편집만, Ctrl+Z
  • 2초 간격 자동 재접속 + 전체 재동기화
편집 · 모델링
  • 테이블/컬럼/관계 편집 폼 PK·UK·FK 플래그, 관계 라벨
  • 도메인 관리 추가·색상·순서 변경, 최대 20개
  • 노드 배치 저장 모두에게 동일하게 보임
  • 변경 이력 50건 조회 + 시점 복원 op마다 전체 스냅샷 저장(방당 1,000개)
임포트 · AI
  • MySQL/MariaDB DDL 임포트 미리보기 → merge/replace 선택
  • FK 없는 스키마 관계 자동 추론 컬럼명·접미사·토큰 점수 기반
  • 도메인 자동 분류 2종 30개 규칙 사전 + Claude(Haiku) LLM 분류, 실패 시 자동 폴백
  • MCP 서버 (SSE·JSON-RPC) 도구 6종: 방 목록/생성, 스키마 조회/교체, DDL 미리보기/적용
  • MCP 연결 가이드 모달 등록 명령 자동 생성, Bearer 토큰 인증 옵션
내보내기 · 불러오기
  • SQL (MySQL/MariaDB) FK 제약·컬럼 COMMENT 포함
  • DBML dbdiagram.io / ERDCloud로 이주 가능
  • PNG (2x) · 독립 실행형 SVG
  • JSON 백업 / 불러오기 전체 교체, undo 가능
방 · 운영
  • 방 분리 워크스페이스 최대 20방 × 동시 10명, 데이터·이력·락 완전 분리
  • 방 목록 5초 폴링 테이블 수·접속자 수 배지
  • 이름만으로 접속 계정·로그인 없음, localStorage 저장
  • Docker 2컨테이너 셀프호스팅 Coolify 배포, /api/health 헬스체크

2경쟁 서비스 한눈에 보기

2025–2026년 기준 웹 조사 결과입니다. 시장은 ① AI 어시스턴트 ② diagram-as-code ③ Git/CI 통합 문서화 ④ 오픈소스 셀프호스팅, 네 축으로 수렴하고 있습니다.

ERDCloud

완전 무료 (광고)
한국 사실상 표준

실시간 동시편집 + 실시간 코멘트를 무료로 제공. 퍼블릭/프라이빗/팀 공유 3단계, SQL 임포트, PDF·PNG·SVG 내보내기.

약점: AI·버전 관리·임베드·다크모드 전부 부재. 부트캠프·사이드 프로젝트 수요를 "무료 협업" 하나로 장악.

dbdiagram.io

무료 ~ $14/월+
Diagram-as-code 원조

DBML 코드로 작성 + AI Assistant(자연어 스키마 생성·diff 미리보기·방언 간 변환). 버전 히스토리, 비밀번호 공유, 임베드, 다크모드, dbdocs 문서 사이트 연동.

Rails·Django 스키마 임포트, PostgreSQL·MySQL·SQL Server 내보내기.

drawSQL

무료(15테이블) ~ $179/월
팀 리뷰 워크플로

캔버스 디스커션 스레드(PR 리뷰처럼 스키마 리뷰) + AI 스키마 리뷰(누락 인덱스 진단). 라이브 커서 멀티플레이어는 $59 플랜부터.

팀 권한(admin/editor/viewer), 버전 히스토리, 200+ 템플릿, Laravel 마이그레이션 출력, 임베드.

ChartDB

오픈소스 + 무료~$19/월
최다 방언 · GitHub ★20k

Smart Query 1개 붙여넣기로 15초 임포트(DB 크리덴셜 불필요). PostgreSQL·MySQL·MSSQL·SQLite·Oracle·Snowflake·BigQuery 등 최광폭 지원.

AI DDL 방언 변환, DB Sync, 자동저장+diff 히스토리, 임베드, DBML 에디터, 셀프호스팅.

Liam ERD

오픈소스 (Apache-2.0)
Git/CI 통합 문서화

GitHub URL 앞에 접두어만 붙이면 ERD 렌더링, CLI로 정적 사이트 생성 → CI/CD 통합. Rails·Prisma·Drizzle 스키마 지원.

읽기 전용 특화(편집 불가). 자동 레이아웃, ⌘K 커맨드 팔레트, 100+ 테이블 성능.

DBeaver · DataGrip

무료/유료 IDE
라이브 DB 시각화

접속 중인 DB를 자동 리버스 엔지니어링해 ERD로. DBeaver PRO는 ERD→DB 포워드 엔지니어링도 지원.

설계 도구가 아닌 보조 기능. 공유 링크·협업·코멘트 없음 — 웹 협업 도구와는 다른 영역.

ERD Studio만 가진 것 — 지킬 자산

MCP 서버 내장은 조사한 어떤 경쟁 서비스에도 없습니다. Claude Code에서 "이 DDL 반영해줘" 한 마디로 방 전원의 화면이 실시간으로 바뀌는 경험은 dbdiagram의 AI Assistant보다 한 단계 위의 워크플로입니다. FK 없는 스키마의 관계 자동 추론과 LLM 도메인 자동 분류도 조사 범위에서 유일했습니다. 아래 로드맵은 이 세 가지를 깎아먹지 않고 증폭하는 방향으로 짰습니다.

4추천 기능 로드맵

우선순위 = (경쟁 필수도 × 확산 효과) ÷ 구현 비용. 난이도는 실제 코드 구조(스냅샷 이력, LLM 연동, op 프로토콜이 이미 있음)를 기준으로 추정했습니다.

Tier 1 — 테이블 스테이크 메우기

단기 · 각 1주 내외

경쟁 서비스 대부분이 갖춘 기본기. 없으면 "왜 ERDCloud 안 쓰고 이걸 써?"라는 질문에 답이 궁해지는 항목들입니다.

1. 방 딥링크 + 읽기전용 공유 링크난이도 하~중확산 효과 최대

현재 SPA 단일 화면이라 URL로 특정 방을 열 수 없습니다. /room/:id 라우팅과 ?view=readonly 파라미터만 있어도 슬랙에 링크 한 줄로 리뷰 요청이 가능해집니다.

근거 — 조사한 웹 기반 5개 서비스 전부 지원. 사내 확산(위키·PR 설명에 링크 첨부)의 전제 조건.

2. 관계 카디널리티 표기 (까마귀발/IE)난이도 하

관계선이 방향·배수 정보 없는 베지어 곡선 하나입니다. FK 구조상 child→parent가 이미 N:1이므로, SVG 마커만 추가해도 기본 표기가 가능하고, 관계 편집 폼에 1:1/1:N 선택지를 더하면 완성됩니다.

근거 — 비교 6개 서비스 중 미지원은 ERD Studio뿐. "ERD 도구"라는 이름값의 최소 요건.

3. PostgreSQL 방언 지원 (임포트 + 내보내기)난이도 중

DDL 파서와 SQL 내보내기가 MySQL/MariaDB 전용입니다. 백엔드 스택이 PostgreSQL인 조직에서 자기 DB 스키마를 못 불러오는 건 아이러니한 공백. 파서에 방언 분기, 내보내기에 방언 선택 드롭다운을 추가합니다.

근거 — MySQL·PostgreSQL 동시 지원은 전 서비스 공통의 최소 공통분모.

4. 미니맵난이도 중

107개 테이블 시드에서 현재 위치를 잃기 쉽습니다. 노드 좌표는 이미 상태에 있으므로 축소 사각형 + 뷰포트 표시 + 클릭 이동만 구현하면 됩니다.

근거 — ChartDB 지원, Liam도 축소 뷰 제공. 대형 스키마가 주 사용례인 이 프로젝트에 특히 유효.

5. 라이트 테마 + PDF 내보내기난이도 하

다크 고정 UI에 CSS 토큰화로 라이트 테마를 추가하고, 기존 SVG 내보내기 파이프라인을 인쇄용으로 확장해 PDF를 지원합니다. 문서·출력물 수요(설계 리뷰 회의)에 대응.

근거 — PDF는 ERDCloud·dbdiagram 지원, 테마 전환은 dbdiagram·ChartDB·Liam 지원.

Tier 2 — 차별화 굳히기

중기 · 각 2~4주

이미 보유한 자산(Anthropic API 연동, 스냅샷 이력, op 프로토콜, MCP)을 지렛대로 쓰는 항목들. 비용 대비 차별화 효과가 가장 큰 구간입니다.

6. AI 스키마 리뷰난이도 중차별화 핵심

누락 인덱스, FK 없는 참조 컬럼, 네이밍 불일치, 타입 불일치(같은 user_no가 테이블마다 다른 타입) 진단. LLM 도메인 분류기가 쓰는 Anthropic API 호출 경로를 그대로 재활용할 수 있어 인프라 비용이 사실상 0입니다.

근거 — drawSQL이 유료(월 $19+) 간판 기능으로 파는 것을 사내 무료로 제공. ERDCloud엔 없는 기능.

7. 이력 diff 뷰어난이도 하~중

서버가 이미 op마다 전체 스키마 스냅샷을 저장하므로(방당 1,000개) 백엔드 작업이 거의 없습니다. 두 시점을 골라 추가/변경/삭제 테이블·컬럼을 나란히 보여주는 프론트 UI만 만들면 됩니다. DDL 임포트 미리보기의 diff 요약 로직도 재활용 가능.

근거 — dbdiagram·drawSQL·ChartDB 모두 제공. "누가 뭘 바꿨지?"는 협업 도구의 핵심 질문.

8. 캔버스 코멘트 / 스티키 노트난이도 중

테이블에 다는 리뷰 스레드와 캔버스 자유 배치 메모. 기존 op 프로토콜에 note.add/comment.add 연산을 추가하면 실시간 동기화·이력·undo가 공짜로 따라옵니다.

근거 — ERDCloud(실시간 댓글)·drawSQL(디스커션 스레드)의 협업 승부처. 설계 리뷰 문화와 직결.

9. 웹 UI 내장 AI 어시스턴트 (자연어 → 스키마)난이도 중

MCP로는 이미 가능하지만 Claude Code 사용자로 한정됩니다. 사이드 패널 채팅에서 "주문·배송 테이블 추가해줘" → 변경안 diff 미리보기 → 적용 흐름을 만들면 비개발 직군까지 커버합니다. 기존 preview/import 경로를 그대로 사용.

근거 — dbdiagram AI Assistant·ChartDB가 주력으로 내세우는 2025~26년 표준 기능.

10. Smart Query식 라이브 스키마 임포트난이도 하~중

ChartDB 방식: DB에 직접 연결하는 대신, 제공된 조회 쿼리 1개를 실행해 나온 JSON을 붙여넣으면 스키마가 임포트됩니다. 크리덴셜을 서버에 저장하지 않아 보안 부담 없이 "살아있는 DB → ERD" 경험을 제공합니다.

근거 — ChartDB ★20k의 핵심 훅. DDL 덤프보다 훨씬 낮은 사용자 마찰.

Tier 3 — 장기 과제

장기 · 수요 확인 후

가치는 있지만 비용이 크거나, 사내 도구라는 포지션에선 수요 검증이 먼저인 항목들.

11. 권한 모델 (방 생성자 = 관리자, editor/viewer)난이도 상

현재 누구나 모든 방을 편집·삭제할 수 있습니다. 사내망에선 당장 문제가 아니지만, 읽기전용 링크(항목 1)를 넘어서는 보호가 필요해지는 시점 — 특히 방 삭제 — 에 대비해야 합니다. 사내 SSO 연동까지 가면 인증 스택 도입이 필요.

12. 임베드 + DBML 임포트난이도 중

읽기전용 뷰(항목 1)가 생기면 iframe 임베드는 그 연장선입니다. 위키·노션에 살아있는 ERD를 심을 수 있게 됩니다. DBML은 현재 출력만 가능한데 임포트를 더하면 dbdiagram 사용자 유입 경로가 열립니다.

13. 멀티 인스턴스 확장난이도 상

락·세션·presence가 서버 메모리 전용이라 단일 인스턴스 전제입니다(코드 주석에도 명시). 사용자가 늘어 수평 확장이 필요해지면 Redis pub/sub 등으로 브로드캐스트·락을 외부화해야 합니다. 20방 × 10명 상한을 올리는 것과 함께 검토.

5포지셔닝 결론

ERD Studio의 경쟁 상대는 기능 목록이 아니라 "그냥 ERDCloud 쓰자"는 관성입니다. ERDCloud는 무료 실시간 협업 하나로 한국 시장을 잡았지만, 데이터가 외부 클라우드에 올라가고 AI·버전 관리·임베드가 전부 공백입니다. ERD Studio는 이미 사내망 셀프호스팅 + 동급 이상의 협업 엔진을 갖췄으므로, Tier 1(공유 링크·카디널리티·방언)만 메워도 "사내 데이터는 사내 도구로"라는 전환 논리가 완성됩니다.

그 다음 승부처는 AI입니다. 시장이 자연어 스키마 생성과 AI 리뷰로 수렴하는 가운데, ERD Studio는 유일하게 MCP 서버를 내장해 에이전트 워크플로에 먼저 도착해 있습니다. Anthropic API 연동도 이미 코드에 있으므로, AI 스키마 리뷰(항목 6)와 내장 어시스턴트(항목 9)는 경쟁사가 유료로 파는 기능을 낮은 비용으로 확보하는 지름길입니다.

요약하면 — 단기에는 기본기 5개로 이탈 명분을 없애고, 중기에는 이미 가진 AI·이력 자산을 UI로 노출해 차별화를 굳히고, 권한·확장은 수요가 증명된 뒤에 갑니다.
