2025–26 시장 트렌드

  • 공백이던 표면 기능 5종(공유 링크, 카디널리티 표기, PostgreSQL 방언, 미니맵, 라이트 테마·PDF)은 v1.3(2026-08-10)에서 전부 해소

최우선 3가지

  • ① 방 딥링크 + 읽기전용 공유 링크 — 도입 장벽 최소, 확산 효과 최대 ✓ v1.3 완료
  • ② 관계 카디널리티 표기 — "ERD처럼 보이게" 만드는 최소 요건 ✓ v1.3 완료
  • ③ AI 스키마 리뷰 — 기존 Anthropic API 연동 재활용으로 drawSQL 유료 기능을 저비용 확보

1구축 배경 — ERDCloud에서 출발한 이유

ERD Studio는 기존에 쓰던 ERDCloud가 사내 조건(FK 제약 없는 운영 DDL · 대규모 테이블 · 다인 동시 편집)에서 드러낸 한계를 메우기 위해 자체 구축했습니다. 항목별 1:1 상세 비교는 구축 배경 · ERDCloud 비교 리포트에 정리되어 있습니다.

기능·UI 한계 — 구축의 직접 계기

  • 관계도 가독성 부족 — 테이블이 많아지면 선이 뒤엉켜 특정 테이블 중심의 관계 파악이 어려움
  • DDL 임포트 시 관계 미표시 — FK 제약이 없는 운영 DDL(사내 대부분)은 관계선이 전혀 그려지지 않음
  • 도메인(업무 영역) 분류 부재 — 테이블을 업무 의미 단위로 묶어 보는 기능이 없음
  • 편집 동선 불편 · 속도 저하 — 테이블/컬럼/관계를 각각 따로 등록, 확대·축소 시 지연 체감

공동편집 한계

  • 편집 중인 테이블 표시 없음 — 같은 테이블을 동시에 수정하다 서로의 작업을 덮어쓸 위험
  • 누가 편집 중인지 알 수 없음 — 작업 조율이 안 되어 중복·충돌 작업 발생
  • 실시간 접속자 목록 부재 — 지금 누가 함께 보고 있는지 확인 불가

자체 구축의 핵심 계기

  • 도메인 단위로 한눈에 보는 스키마 — DDL만 올리면 테이블명·코멘트 의미를 분석해 회원/주문/결제 등 업무 도메인별 자동 분류·색상 구분
  • 테이블 중심의 관계 탐색 — 테이블 선택 시 참조(→)·역참조(←) 강조, FK 제약이 없어도 컬럼명 규칙(user_no → USER)으로 관계 자동 추론
  • 공동편집 안정성 — 테이블 단위 편집 락 + 편집 중 사용자 표시 + 실시간 접속자 목록

2경쟁 서비스 한눈에 보기

2025–2026년 기준 웹 조사 결과입니다.

ERDCloud

완전 무료 (광고)
한국 사실상 표준

실시간 동시편집 + 실시간 코멘트를 무료로 제공. 퍼블릭/프라이빗/팀 공유 3단계, SQL 임포트, PDF·PNG·SVG 내보내기.

약점: AI·버전 관리·임베드·다크모드 전부 부재. 부트캠프·사이드 프로젝트 수요를 "무료 협업" 하나로 장악.

dbdiagram.io

무료 ~ $14/월+
Diagram-as-code 원조

DBML 코드로 작성 + AI Assistant(자연어 스키마 생성·diff 미리보기·방언 간 변환). 버전 히스토리, 비밀번호 공유, 임베드, 다크모드, dbdocs 문서 사이트 연동.

Rails·Django 스키마 임포트, PostgreSQL·MySQL·SQL Server 내보내기.

drawSQL

무료(15테이블) ~ $179/월
팀 리뷰 워크플로

캔버스 디스커션 스레드(PR 리뷰처럼 스키마 리뷰) + AI 스키마 리뷰(누락 인덱스 진단). 라이브 커서 멀티플레이어는 $59 플랜부터.

팀 권한(admin/editor/viewer), 버전 히스토리, 200+ 템플릿, Laravel 마이그레이션 출력, 임베드.

ChartDB

오픈소스 + 무료~$19/월
최다 방언 · GitHub ★20k

Smart Query 1개 붙여넣기로 15초 임포트(DB 크리덴셜 불필요). PostgreSQL·MySQL·MSSQL·SQLite·Oracle·Snowflake·BigQuery 등 최광폭 지원.

AI DDL 방언 변환, DB Sync, 자동저장+diff 히스토리, 임베드, DBML 에디터, 셀프호스팅.

Liam ERD

오픈소스 (Apache-2.0)
Git/CI 통합 문서화

GitHub URL 앞에 접두어만 붙이면 ERD 렌더링, CLI로 정적 사이트 생성 → CI/CD 통합. Rails·Prisma·Drizzle 스키마 지원.

읽기 전용 특화(편집 불가). 자동 레이아웃, ⌘K 커맨드 팔레트, 100+ 테이블 성능.

DBeaver · DataGrip

무료/유료 IDE
라이브 DB 시각화

접속 중인 DB를 자동 리버스 엔지니어링해 ERD로. DBeaver PRO는 ERD→DB 포워드 엔지니어링도 지원.

설계 도구가 아닌 보조 기능. 공유 링크·협업·코멘트 없음 — 웹 협업 도구와는 다른 영역.

ERD Studio만 가진 것 — 지킬 자산

MCP 서버 내장은 조사한 어떤 경쟁 서비스에도 없습니다. Claude Code에서 "이 DDL 반영해줘" 한 마디로 방 전원의 화면이 실시간으로 바뀌는 경험은 dbdiagram의 AI Assistant보다 한 단계 위의 워크플로입니다. FK 없는 스키마의 관계 자동 추론과 LLM 도메인 자동 분류도 조사 범위에서 유일했습니다. 아래 로드맵은 이 세 가지를 깎아먹지 않고 증폭하는 방향으로 짰습니다.

4추천 기능 로드맵

우선순위 = (경쟁 필수도 × 확산 효과) ÷ 구현 비용. 난이도는 실제 코드 구조(스냅샷 이력, LLM 연동, op 프로토콜이 이미 있음)를 기준으로 추정했습니다.

Tier 1 — 테이블 스테이크 메우기

단기 · 각 1주 내외✓ 5종 전체 완료 — v1.3 (2026-08-10)

경쟁 서비스 대부분이 갖춘 기본기. 없으면 "왜 ERDCloud 안 쓰고 이걸 써?"라는 질문에 답이 궁해지는 항목들입니다. 아래 5개 항목은 v1.3에서 모두 구현됐습니다.

1. 방 딥링크 + 읽기전용 공유 링크✓ 완료난이도 하~중확산 효과 최대

현재 SPA 단일 화면이라 URL로 특정 방을 열 수 없습니다. /room/:id 라우팅과 ?view=readonly 파라미터만 있어도 슬랙에 링크 한 줄로 리뷰 요청이 가능해집니다.

근거 — 조사한 웹 기반 5개 서비스 전부 지원. 사내 확산(위키·PR 설명에 링크 첨부)의 전제 조건.

2. 관계 카디널리티 표기 (까마귀발/IE)✓ 완료난이도 하

관계선이 방향·배수 정보 없는 베지어 곡선 하나입니다. FK 구조상 child→parent가 이미 N:1이므로, SVG 마커만 추가해도 기본 표기가 가능하고, 관계 편집 폼에 1:1/1:N 선택지를 더하면 완성됩니다.

근거 — 비교 6개 서비스 중 미지원은 ERD Studio뿐. "ERD 도구"라는 이름값의 최소 요건.

3. PostgreSQL 방언 지원 (임포트 + 내보내기)✓ 완료난이도 중

DDL 파서와 SQL 내보내기가 MySQL/MariaDB 전용입니다. 백엔드 스택이 PostgreSQL인 조직에서 자기 DB 스키마를 못 불러오는 건 아이러니한 공백. 파서에 방언 분기, 내보내기에 방언 선택 드롭다운을 추가합니다.

근거 — MySQL·PostgreSQL 동시 지원은 전 서비스 공통의 최소 공통분모.

4. 미니맵✓ 완료난이도 중

107개 테이블 시드에서 현재 위치를 잃기 쉽습니다. 노드 좌표는 이미 상태에 있으므로 축소 사각형 + 뷰포트 표시 + 클릭 이동만 구현하면 됩니다.

근거 — ChartDB 지원, Liam도 축소 뷰 제공. 대형 스키마가 주 사용례인 이 프로젝트에 특히 유효.

5. 라이트 테마 + PDF 내보내기✓ 완료난이도 하

다크 고정 UI에 CSS 토큰화로 라이트 테마를 추가하고, 기존 SVG 내보내기 파이프라인을 인쇄용으로 확장해 PDF를 지원합니다. 문서·출력물 수요(설계 리뷰 회의)에 대응.

근거 — PDF는 ERDCloud·dbdiagram 지원, 테마 전환은 dbdiagram·ChartDB·Liam 지원.

Tier 2 — 차별화 굳히기

중기 · 각 2~4주

이미 보유한 자산(스냅샷 이력, op 프로토콜, MCP)을 지렛대로 쓰는 항목들. LLM 없이 동작하므로 운영 전제가 없고, 비용 대비 차별화 효과가 가장 큰 구간입니다.

6. 이력 diff 뷰어✓ 완료 — v1.5 (2026-08-24)난이도 하~중

v1.5에서 구현 — 예상대로 백엔드는 스냅샷 쌍을 돌려주는 GET /history/{id}/diff 하나로 충분했고, 이력 패널 각 행의 '비교' 버튼이 직전 시점과의 변경점을 도메인/테이블(컬럼 포함)/관계/메모 단위로 ＋추가/△변경/－삭제 색상 모달에 보여줍니다. diff 계산은 프론트가 담당.

근거 — dbdiagram·drawSQL·ChartDB 모두 제공. "누가 뭘 바꿨지?"는 협업 도구의 핵심 질문.

7. 캔버스 코멘트 / 스티키 노트✓ 스티키 노트 완료 — v1.4 (2026-08-14)난이도 중

캔버스 자유 배치 메모는 v1.4에서 memo.add/apply/delete/move 연산으로 구현 — 예상대로 기존 op 프로토콜에 얹어 실시간 동기화·이력·undo가 그대로 따라왔습니다. v1.5에서는 메모–테이블 연결(최대 10개, 클릭 시 연결 테이블 하이라이트)과 크기 자유 조절(memo.resize)로 확장됐습니다. 남은 절반은 테이블에 다는 리뷰 스레드(댓글)입니다.

근거 — ERDCloud(실시간 댓글)·drawSQL(디스커션 스레드)의 협업 승부처. 설계 리뷰 문화와 직결.

8. Smart Query식 라이브 스키마 임포트난이도 하~중

ChartDB 방식: DB에 직접 연결하는 대신, 제공된 조회 쿼리 1개를 실행해 나온 JSON을 붙여넣으면 스키마가 임포트됩니다. 크리덴셜을 서버에 저장하지 않아 보안 부담 없이 "살아있는 DB → ERD" 경험을 제공합니다.

근거 — ChartDB ★20k의 핵심 훅. DDL 덤프보다 훨씬 낮은 사용자 마찰.

Tier 3 — 장기 과제

장기 · 수요 확인 후

가치는 있지만 비용이 크거나, 사내 도구라는 포지션에선 수요 검증이 먼저인 항목들. 서버 측 LLM이 필수인 AI 기능(항목 9·10)도 여기에 둡니다 — Anthropic API 키 설정과 외부(또는 사내 프록시) 아웃바운드 호출이 운영 전제이고, 키가 없으면 폴백 없이 기능을 숨겨야 하기 때문입니다.

9. AI 스키마 리뷰난이도 중서버 LLM 필수차별화 핵심

누락 인덱스, FK 없는 참조 컬럼, 네이밍 불일치, 타입 불일치(같은 user_no가 테이블마다 다른 타입) 진단. LLM 도메인 분류기가 쓰는 Anthropic API 호출 경로를 그대로 재활용할 수 있어 인프라 비용이 사실상 0이지만, API 키가 설정된 배포에서만 동작합니다.

근거 — drawSQL이 유료(월 $19+) 간판 기능으로 파는 것을 사내 무료로 제공. ERDCloud엔 없는 기능.

10. 웹 UI 내장 AI 어시스턴트 (자연어 → 스키마)난이도 중서버 LLM 필수

MCP로는 이미 가능하지만 Claude Code 사용자로 한정됩니다(이 경우 LLM은 클라이언트 쪽에 있어 서버 키가 불필요). 사이드 패널 채팅에서 "주문·배송 테이블 추가해줘" → 변경안 diff 미리보기 → 적용 흐름을 만들면 비개발 직군까지 커버합니다. 기존 preview/import 경로를 그대로 쓰되, 자연어 → 스키마 변환은 서버 측 LLM 호출이 필수라 키 미설정 시 패널 자체를 숨기는 조건부 UI가 전제입니다.

근거 — dbdiagram AI Assistant·ChartDB가 주력으로 내세우는 2025~26년 표준 기능.

11. 권한 모델 (방 생성자 = 관리자, editor/viewer)난이도 상

현재 누구나 모든 방을 편집·삭제할 수 있습니다. 사내망에선 당장 문제가 아니지만, 읽기전용 링크(항목 1)를 넘어서는 보호가 필요해지는 시점 — 특히 방 삭제 — 에 대비해야 합니다. 사내 SSO 연동까지 가면 인증 스택 도입이 필요.

12. 임베드 + DBML 임포트난이도 중

읽기전용 뷰(항목 1)가 생기면 iframe 임베드는 그 연장선입니다. 위키·노션에 살아있는 ERD를 심을 수 있게 됩니다. DBML은 현재 출력만 가능한데 임포트를 더하면 dbdiagram 사용자 유입 경로가 열립니다.

13. 멀티 인스턴스 확장난이도 상

락·세션·presence가 서버 메모리 전용이라 단일 인스턴스 전제입니다(코드 주석에도 명시). 사용자가 늘어 수평 확장이 필요해지면 Redis pub/sub 등으로 브로드캐스트·락을 외부화해야 합니다. 20방 × 10명 상한을 올리는 것과 함께 검토.

5포지셔닝 결론

ERD Studio의 경쟁 상대는 기능 목록이 아니라 "그냥 ERDCloud 쓰자"는 관성입니다. ERDCloud는 무료 실시간 협업 하나로 한국 시장을 잡았지만, 데이터가 외부 클라우드에 올라가고 AI·버전 관리·임베드가 전부 공백입니다. ERD Studio는 이미 사내망 셀프호스팅 + 동급 이상의 협업 엔진을 갖췄으므로, Tier 1(공유 링크·카디널리티·방언)만 메워도 "사내 데이터는 사내 도구로"라는 전환 논리가 완성됩니다. ✓ Tier 1은 v1.3(2026-08-10)에서 전체 완료 — 이제 이 전환 논리가 실제로 성립합니다.

그 다음 승부처는 AI입니다. 시장이 자연어 스키마 생성과 AI 리뷰로 수렴하는 가운데, ERD Studio는 유일하게 MCP 서버를 내장해 에이전트 워크플로에 먼저 도착해 있습니다. Anthropic API 연동도 이미 코드에 있으므로 AI 스키마 리뷰(항목 9)와 내장 어시스턴트(항목 10)는 경쟁사가 유료로 파는 기능을 낮은 비용으로 확보하는 지름길이지만, 서버 측 LLM(API 키·아웃바운드 호출)이 필수라는 운영 전제 때문에 장기 과제로 분류합니다 — 그전까지 AI 수요는 서버 키가 필요 없는 MCP 경로가 담당합니다.

요약하면 — 단기 기본기 5개(완료)로 이탈 명분을 없앴고, 중기 구간도 진행 중입니다: 이력 diff 뷰어(항목 6)는 v1.5에서 완료됐고, 캔버스 메모(항목 7)는 테이블 연결·크기 조절까지 확장됐습니다. 남은 중기 항목은 리뷰 스레드(7 후반)와 라이브 임포트(8)이며, AI 기능·권한·확장은 운영 전제와 수요가 갖춰진 뒤에 갑니다.
